# Durimage

榴莲病虫害拍照 PWA。工人不用登录 Google，拍的照片全部存进**管理员（你）的 Google Drive**。中文 / English / Bahasa Melayu。

## 运作方式

```
1. 手机 ──团队密码 + 照片资料──▶ Apps Script（用你的账号执行）──开上传通道──▶ Google Drive
2. 手机 ──────────────── 原图直接上传 ────────────────────────────────▶ 你的 Google Drive
```

- App 是纯静态网页，没有服务器。
- Apps Script 用你的 Google 账号运行，只负责验证密码、开一个"只能写这一张照片"的上传通道。照片原图由手机直接传进你的 Drive，所以没有大小限制，也不会被压缩。
- 你的 Google 登录凭证不会传到手机上。
- 团队密码存在 Apps Script 的 Script Properties 里，不在程序码、也不在 GitHub。

## 工人怎么用

1. 打开 App，第一次要做两步：
   - **第 1 步：输入团队密码**（需要网络，密码错了不能继续）
   - **第 2 步：输入名字**（没填不能继续）
2. 按中间快门拍照（或从相册选）→ 选文件夹 → 可写备注 → 保存。
3. 照片先存在手机里，有网络就自动上传；果园没信号会排队，有网络再打开 App 会继续传。

**Google Sheet `Durimage 照片记录`**：**有写注解**或**仅训练集**（`NA`）的照片会加一行；其他照片不会进 Sheet（全部照片在 Drive 文件夹里都有）。

- 只有一个 Sheet、一个分页，**最新的注解在最上面**。
- Sheet 第一次有注解时由 Apps Script 自动建立，放在 `Durimage` 总文件夹里，你不用自己建。
- 栏位：拍摄时间 · 文件夹 · 拍摄者 · 注解 · 照片（链接）· 文件名 · GPS · 地图（链接）· 原图/压缩 · **核实结果** · **管理员备注** · 果园 · 树号 · 来源 · 用途
- 后面四栏是新加的，永远加在最后面（防重复写入靠"文件名"那一栏的位置）。旧的 Sheet 会自动补上新标题。
- 最后两栏（金色标题）留给你自己填，例如专家确认后的正确病名。
- 标题行已冻结、已开筛选，可以按文件夹、拍摄者、日期筛选。
- Sheet 里不显示缩图（私人照片无法用 `IMAGE()` 显示），点「打开照片」看原图。
- 如果你把 Sheet 删掉，下一条注解会自动建一个新的。

上传到 Drive 的照片：

**文件名只用英文**（字母、数字、`-`；`_` 用来分隔栏位），方便下载、解压缩和以后用程序处理：

```
durian_<文件夹>_<果园>_<树号>-p<第几张>_<日期_时间>_<名字>_<随机码>.jpg

durian_Disease-5-NOV-26_BENTONG-A_t03-p02_20261105_143047_Ah-Ming_7e01bd.jpg    流水号
durian_Disease-5-NOV-26_BENTONG-A_tagB-12-p01_20261105_143105_Ah-Ming_c45a10.jpg 树牌号码
durian_Disease-5-NOV-26_NA_tNA-p01_20230312_101544_Ah-Ming_9b2e41.jpg            旧照片（不知道果园和树）
```

- 文件夹：取文件夹名称里的英文部分；完全没有英文时用文件夹 ID 的前 6 个字。
- 果园、树牌：工人输入，只能英文、数字和 `-`，自动转大写。
- `NA` / `tNA`：不知道果园 / 不知道树。**有任何一个 `NA` 的照片，只能放进训练集。**
- 名字：工人的英文名字或拼音。
- 随机码：保证文件名不会重复（防重复上传也靠它）。
- 设置里关掉"记录果园和树号"时，文件名是 `durian_<文件夹>_<日期_时间>_<名字>_<随机码>.jpg`。
- 照片的 Drive 说明里另有 `Orchard:`、`Tree:`、`Source:`、`Use:` 几行；Drive 文件属性（properties）也存了 `orchard`、`tree`、`source`、`use`、`sha256`。

**重复照片**：每张照片会计算指纹（SHA-256）。同一张照片之前上传过（不管是哪支手机），就不会再存一次。

## 一次性设置（管理员）

### 1. 在 Drive 建文件夹

建一个总文件夹，例如 `Durimage`，里面建分类子文件夹（`果腐病`、`蛀果虫`、`叶斑病`…）。
App 会自动列出总文件夹下的**子文件夹**。以后新增子文件夹，工人在 App 里点「刷新」就会出现。

打开总文件夹，复制网址最后那段 ID：
`https://drive.google.com/drive/folders/`**`1AbCdEf...`** ← 这段

### 2. 建 Apps Script

1. 打开 <https://script.google.com> → 新项目，命名 `Durimage`。
2. 把 `apps-script/Code.gs` 的内容整个贴进去，取代原本的代码，存档。
3. 左边 ⚙️ **项目设置（Project Settings）** → 拉到最下 **脚本属性（Script Properties）** → 新增两个：

   | 属性 | 值 |
   |---|---|
   | `TEAM_PASSWORD` | 团队密码（拍照的人用） |
   | `REVIEW_PASSWORD` | 审核密码（专家用） |
   | `ADMIN_PASSWORD` | 管理员密码（你自己用） |
   | `ROOT_FOLDER_ID` | 第 1 步复制的文件夹 ID |

   （之后会自动多出一个 `LOG_SHEET_ID`，是注解 Sheet 的 ID，不用理它。）

4. 右上 **部署（Deploy）→ 新部署（New deployment）** → 类型选 **网页应用（Web app）**：
   - 执行身份（Execute as）：**我（Me）**
   - 谁可以访问（Who has access）：**任何人（Anyone）**
5. 按部署，第一次会要求授权你的 Google 账号（会要求 Drive、Google Sheets 和"连接外部服务"三项权限：Sheets 用来写注解，外部服务用来开上传通道）（会出现"Google 尚未验证此应用"，按 *Advanced → Go to Durimage* 继续，因为这是你自己的脚本）。
6. 复制 **网页应用网址**（结尾是 `/exec`）。

### 3. 把网址填进 App

打开 `config.js`，填入：

```js
SCRIPT_URL: 'https://script.google.com/macros/s/xxxxxxxx/exec',
```

提交到 GitHub，GitHub Pages 会自动更新。

## 分享 App

右上角 QR 按钮（或 设置 → 分享 App）会显示 App 网址的 QR code，对方用手机相机扫描就能打开。QR 里**不含**团队密码，要另外告诉对方。

## 更改团队密码

1. 打开 <https://script.google.com> → Durimage 项目 → ⚙️ 项目设置 → 脚本属性。
2. 编辑 `TEAM_PASSWORD`，存档。**马上生效，不用重新部署。**
3. 工人的手机下次上传或刷新文件夹时，App 会跳出「团队密码已更改」画面要他们输入新密码。还没上传的照片不会丢，输入后会继续上传。

> **v1.4.0 改了 `Code.gs`**（重复照片检查、Drive 属性、Sheet 新栏位），请更新并重新部署一次。
> **v1.5.0 改了 `Code.gs`**（审核功能），而且要在 Script Properties 新增 `REVIEW_PASSWORD` 和 `ADMIN_PASSWORD`，然后重新部署一次。
> **v1.5.1 改了 `Code.gs`**（「送审」分页多一栏 `marksJSON`，存拍照者的标记；旧的分页会自动补上标题），请更新并重新部署一次。
> **v1.6.0 改了 `Code.gs`**（通知）：更新代码后先在编辑器选 `setupNotifications` 按 Run 一次（会要求新的授权，装 5 分钟定时器），再重新部署。
> **v1.6.3 / v1.6.4 改了 `Code.gs`**（推送记录分页含设备栏、测试通知也记录、只在手机真的失效时才移除），请更新并重新部署（不用再按 Run）。
> 只有改 `Code.gs` 的代码才需要重新部署：部署 → 管理部署 → ✏️ 编辑 → 版本选「新版本」→ 部署（网址不变）。

## 果园和树号

- 首页显示目前的**果园**和**树号**，点一下可以改。没设果园时按快门会先请你设定。
- **流水号**（默认）：每次到果园从第 1 棵开始，按「下一棵树」+1；隔天打开会问要继续还是从 1 开始。
- **树牌号码**：树上有挂牌时用，按「下一棵树」输入树牌（预先填好上一个 +1）。在 设置 → 树的编号方式 切换，每个果园各自记住。
- 果园和树号在**照片从相机回来那一刻**就固定，之后再按「下一棵树」不会影响已经拍好、还在排队的照片。
- **从相册上传**：果园、树号选填；打开「旧照片」开关就是 `NA` / `tNA`，只能用于训练集。

## 三种身份

App 登录时用哪一组密码，就是哪一种身份（设置 → 身份 → 切换身份 可以换）：

| | 拍照者（`TEAM_PASSWORD`） | 审核员（`REVIEW_PASSWORD`） | 管理员（`ADMIN_PASSWORD`） |
|---|---|---|---|
| 拍照、果园、树号、上传 | ✅ | | ✅ |
| 初步判断（多选 + 手写 + 确定/不确定） | ✅ | | ✅ |
| 送审（单张 / 首页「选择」多张） | ✅ | | ✅ |
| 看自己照片的审核结果 | ✅ | | ✅ |
| 待审核清单、放大、改正、手写补充、留言、画图标注 | | ✅ | ✅（首页「审核中心」） |
| 看得到其他审核员的结果 | | ❌ 互相看不到 | ✅ 全部 |
| 管理病虫害清单（设置 → 病虫害清单） | | | ✅ |

- 审核员第一次登录要写名字（中英马文都可以），审核记录会显示是谁审核的。
- 审核员修改审核时会新增一个版本，旧版本保留（审核记录）。
- 拍照的人也可以在照片上画标记（保存时或在照片详情），送审后改了会自动重新送审。审核员看到的拍照者标记是**虚线**，自己的是**实线**，也可以关掉拍照者的标记自己先看。
- 审核员画的标注不会改到原图：标注资料存在 Sheet，画了标注的副本存在 Drive 的 `_审核标记` 文件夹（这个文件夹不会出现在 App 的文件夹清单里）。
- Google Sheet `Durimage 照片记录` 会多出几个分页：`送审`（每张送审照片一行）、`审核`（每次审核一行，包括修改）、`类别`（病虫害清单，也可以直接在 Sheet 改）、`缩图`（隐藏，App 用）。

## 通知

**App 内提醒**（不用设置就有）：
- 拍照的人 / 管理员：首页出现「David 审核了你的 3 张照片 · 查看」，点开是这几张照片的结果。
- 审核员 / 管理员的审核中心：清单上方出现「Ali 提交了 5 张新照片」。
- iPhone 主画面 App 图示上的数字：拍照的人 = 有新审核结果的照片数；审核员 = 待审核数。

**手机推送**（App 关着也会响，要设置一次 Firebase）：
- 有照片送审 → 审核员和管理员收到「Ali 提交了 5 张照片，请审核」。
- 审核完成 → 拍照的人收到「David 审核了你的 3 张照片（2 张同意，1 张需要改正）」；管理员收到全部专家的审核摘要。
- **每 5 分钟合并一次**：同一段时间内的事件合成一条通知，不会一直响。
- 每支手机在 设置 → 通知 自己开关；默认全开。重复送审（例如修改标记）不会再通知。
- 拍照的人是靠 App 里填的**名字**对上的：名字不要重复。
- iPhone 要 **iOS 16.4 以上**，而且要**从主画面打开 App**（Safari → 分享 → 加入主画面），才能收推送。

### 设置手机推送（一次，约 15 分钟）

1. 打开 <https://console.firebase.google.com> → **Create a project**（名字例如 `Durimage`，Google Analytics 可以关掉）。
2. 项目首页 → **Add app** → 选 **Web**（`</>` 图示）→ 名字 `Durimage` → **Register app**。画面会显示 `const firebaseConfig = { ... }`，把整段复制下来。
3. ⚙️ **Project settings** → **Cloud Messaging** 分页 → 拉到 **Web configuration → Web Push certificates** → **Generate key pair**，复制那串 key。
4. ⚙️ **Project settings** → **Service accounts** 分页 → **Generate new private key** → **Generate key**，会下载一个 `.json` 文件。用记事本打开，全选复制。**这个文件等于密码，不要传给任何人。**
5. Apps Script → ⚙️ **Project Settings** → **Script Properties** → 加三个：

   | Property | Value |
   |---|---|
   | `FCM_WEB_CONFIG` | 第 2 步复制的 `firebaseConfig` 整段 |
   | `FCM_VAPID_KEY` | 第 3 步的 key |
   | `FCM_SERVICE_ACCOUNT` | 第 4 步 `.json` 文件的全部内容 |

6. 编辑器上方的函数选单选 **`setupNotifications`** → 按 **Run** → 授权。下面的 Execution log 应该出现两行 ✅。
7. **Deploy → Manage deployments → ✏️ Edit → New version → Deploy**。
8. 手机：设置 → 通知 → **开启手机推送** → 允许 → 按「发送测试通知」。

> 没设置 Firebase 也没关系：App 内提醒照样有，只是手机不会响。

## 首页筛选

「最近照片」旁边的 **筛选** 可以按果园、树、病虫害、日期、状态（有注解 / 仅训练 / 不确定 / 未送审 / 等待审核 / 已审核）、文件夹，或打字搜索。手机里保留最近 **1000 张**已上传照片的预览图，没信号也能找出来给别人看。

## 发布新版本（自动更新）

用户的手机会自动更新，不需要重新安装：

1. 在 `changelog.js` **最上面**加一条新版本（版本号、发布时间、三种语言的更新内容）。
2. 把 `sw.js` 里的 `VERSION` 改成同一个版本号。
3. 推到 GitHub，GitHub Pages 一两分钟后会更新。
4. 用户下次打开 App 或从别的 App 切回来时，会自动换成新版，并跳出"已更新到 vX.Y.Z"。正在上传、开着相机或正在保存照片时不会打断。

## 安全说明

- 团队密码只能挡住"拿到网址就乱传"的情况，不是高强度保护。人员离开团队时建议改密码。
- Apps Script 只允许把照片存进总文件夹的直接子文件夹，只收图片，单张上限 15 MB。

## 本地测试

```bash
python3 -m http.server 8765
# 打开 http://localhost:8765
```

`config.js` 的 `SCRIPT_URL` 留空时是演示模式：假文件夹、假上传，任何密码都可以。
